# Use Case: Apply a URL Profile

## Overview

**Use Case ID:** UC-007
**Use Case Name:** Apply a URL Profile
**Primary Actor:** *(extends UC-004)*
**Goal:** Give the active profile's rules precedence over the global rules
**Status:** Draft

Extends UC-004 (determine the value for a field). Depends on UC-017 for which profile is
active.

**Traces to:** FR-031, FR-045

## Preconditions

- A fill is running, and UC-017 has resolved which profile governs the page

## Main Success Scenario

1. The system forms one ordered rule list: the active profile's rules, then the global rules.
2. The system compiles that list once for the fill.
3. For each field, the first rule in the list that matches wins (UC-004).
4. The report names the rule that produced each value, so which list it came from is visible in
   its name.

## Alternative Flows

### A1: No profile is active

**Trigger:** UC-017 resolved no profile
**Flow:**

1. The list is the global rules alone.
2. The engine behaves exactly as it did before profiles existed.

### A2: A profile rule and a global rule both match a field

**Trigger:** Two rules match the same field (step 3)
**Flow:**

1. The profile rule wins, because it is earlier in the list.
2. No separate precedence pass runs, and no warning is given: this is the intended use.

### A3: A profile rule cannot run

**Trigger:** A profile rule's pattern will not compile (step 2)
**Flow:**

1. It is kept in the list carrying its problem, and named in the report as skipped (DD-005).
2. The next matching rule — possibly a global one — produces the value.

### A4: A field confirms another field

**Trigger:** The field mirrors an earlier one (UC-006)
**Flow:**

1. Mirroring wins over every rule, profile rules included.
2. The overridden rule is named in the report rather than dropped in silence.

## Postconditions

### Success Postconditions

- Every value came from the first matching rule in one ordered list
- A profile rule beat a global rule wherever both matched
- The global rules still applied wherever no profile rule did

### Failure Postconditions

- Not applicable: a rule that cannot run falls through to the next, and a fill with no usable
  rules is the persona-driven engine, which always works.

## Business Rules

### BR-007-1: Precedence is position, not a separate concept

The profile's rules are concatenated ahead of the global list and first-match-wins does the
rest. There is no rule-versus-rule comparison anywhere in the engine.

This is what makes FR-031 a single sentence a user can hold in their head — and it is why
`compileRules` has taken an already-ordered list since Phase 2, two phases before there was
anything to put in front of it.

### BR-007-2: The profile adds, it does not replace

See BR-014-4. The global rules still run after the profile's.

### BR-007-3: One compilation per fill, not per page-agent batch

The concatenated list is compiled once when the fill begins (NFR-025, ND-15). A page with
frames sends one batch per frame per pass, and compiling per batch would rebuild every pattern
on every pass of every frame.
