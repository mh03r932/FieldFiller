# Use Case: Delete a URL Profile

## Overview

**Use Case ID:** UC-016
**Use Case Name:** Delete a URL Profile
**Primary Actor:** Power User
**Goal:** Remove a profile and the rules in it
**Status:** Draft

Includes UC-024 (persist and propagate).

**Traces to:** FR-046

## Preconditions

- The Power User has the settings open
- The profile exists

## Main Success Scenario

1. The Power User asks to delete a profile.
2. The system asks for confirmation, naming the profile and how many rules will go with it.
3. The Power User confirms.
4. The system removes the profile and its rules, stores the change (UC-024), and announces it.
5. Pages the profile governed fall to the next matching profile, or to the global rules alone.

## Alternative Flows

### A1: The Power User declines

**Trigger:** The confirmation is dismissed (step 3)
**Flow:**

1. Nothing is changed and nothing is stored.
2. The use case ends.

### A2: The profile contains no rules

**Trigger:** The profile's rule list is empty (step 2)
**Flow:**

1. The confirmation names the profile and does not mention a rule count.
2. Everything else is as the main scenario.

### A3: The change cannot be stored

**Trigger:** Storage rejects the change (step 4) — see UC-024 A2
**Flow:**

1. The profile remains in force.
2. The system reports that the change did not take effect, and why.

## Postconditions

### Success Postconditions

- The profile and its rules are gone
- Pages it governed are governed by the next matching profile, or by the global rules
- The stored settings and what the user sees agree

### Failure Postconditions

- The profile and every rule in it remain
- No profile has been left partly deleted

## Business Rules

### BR-016-1: Deleting a profile is confirmed, unlike deleting a rule

This is the one place the profile list deliberately departs from the rule editor beside it,
and the departure is about *how much work is at stake*.

BR-011-1's argument for a rule is that a confirmation taxes every user to protect the one who
misclicked, and a rule is one line to rewrite. A profile can hold an afternoon's work, and the
undo offer that makes rule deletion safe lives only as long as the page does — which is not a
proportionate safety net for a rule set the user may have built over weeks.

### BR-016-2: The confirmation states the cost

The profile's name and the number of rules going with it. "Delete this profile?" and "delete
this profile and the 14 rules in it?" are different questions, and only the second is the one
actually being asked.

### BR-016-3: A profile's rules go with it

They are not returned to the global list. A rule written inside a profile was scoped
deliberately, and moving it to global scope would apply it to every page the user visits —
turning a deletion into a silent widening, which is the opposite of what was asked for.
